I work on the boundary where software reliability meets physical hardware. On one side that's Kubernetes, CI/CD and observability. On the other it's ESP32 firmware, sensors and power systems. Both reward the same habits: design for failure, measure everything, automate the recovery.

☸️ Research spotlight: multi-cluster failover for IoT
<img src="assets/failover.svg" width="100%" alt="Animated multi-cluster Kubernetes failover diagram"/>
My final-year research studies how IoT telemetry pipelines survive the loss of an entire Kubernetes cluster: health-check-driven routing, warm standby, automatic recovery, and what the failover actually costs in latency and data loss.
